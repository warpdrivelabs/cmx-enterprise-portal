# 字段属性面板渲染体系（cmx-field-schema / cmx-field-adapter / cmx-field-ui）

> 一句话：`cmx-field-ui.js` 是**纯函数渲染器**，产出 HTML 字符串；**DCT / DOC / FLC / 设计器列模型** 四端元数据维护页共用它。改它 = 改全部元数据维护页的字段属性面板。

```
            ┌─────────────────────────────────────────────────────────────┐
            │   FIELD_SCHEMA（cmx-field-schema.js）                       │
            │   三端属性并集 + appliesTo 端过滤 + placement + section     │
            │   单一事实来源（属性定义 / 值域 / 可见性钩子 / 控件类型）   │
            └─────────────────────────────────────────────────────────────┘
                   ▲                                  ▲
                   │ fieldsFor / panelSectionsFor     │ placementOf / editorPropsFor / inlineFieldsFor
                   │                                  │
   ┌───────────────┴──────────────┐    ┌──────────────┴───────────────────┐
   │  cmx-field-adapter.js        │    │  cmx-field-ui.js（纯函数）        │
   │  读 get() 写 set()           │    │  renderFieldTable(inline)         │
   │  schema 规范key ↔ 各端存储键 │    │  renderFieldPanel(panel，按 section)│
   │  makeDctAdapter / makeFlcAdapter │  产出 HTML 字符串，无副作用      │
   └───────────────┬──────────────┘    └──────────────┬───────────────────┘
                   │ adapter.get(field,key)             │ HTML 字符串
                   └──────────────┬─────────────────────┘
                                  ▼
   ┌──────────────────────────────────────────────────────────────────────┐
   │  四端宿主（各挂自己的 _handleClick / _handleInput + shadowRoot 样式） │
   │   • 定义中心 DCT/DOC —— portal-definition-manager.js                 │
   │   • 弹性组合 FLC     —— portal-flexible-combination-manager.js       │
   │   • 设计器列模型     —— models-props-columnmodel.js                  │
   │   • 设计器检查器     —— model-props-inspector.js                     │
   └──────────────────────────────────────────────────────────────────────┘
```

---

## 1. 四端共用关系（核心结论）

`renderFieldPanel` / `renderFieldTable` 由 `packages/cmx-data-comp/src/index.js` 统一导出，四个宿主通过 npm 包 import 共用：

| 宿主页面 | 文件 | 调用端 `end:` | adapter |
|---|---|---|---|
| 定义中心 — 数据字典 DCT | `../../../cmx-portal-manager` | `'DCT'` | `makeDctAdapter({ typeCaps })` |
| 定义中心 — 业务单据 DOC | 同上（按 `data-kind` 切换） | `'DOC'` | `makeDctAdapter({ typeCaps })` |
| 弹性组合 FLC | `../../../cmx-portal-manager` | `'FLC'` | `makeFlcAdapter()` |
| 设计器 — 列模型 | `../../../cmx-html-designer` | `'FLC'` | `makeFlcAdapter()` |
| 设计器 — 检查器面板 | `../../../cmx-html-designer` | `'FLC'` | `makeFlcAdapter()` |

> DCT 与 DOC 共用 `portal-definition-manager.js`，由 `_schemaEnd()`（`/DOC/.test(this._kind) ? 'DOC' : 'DCT'`）决定渲染端。

**统一导出**（`packages/cmx-data-comp/src/index.js:101`）：

```js
export { renderFieldTable, renderFieldPanel } from './lib/cmx-field-ui.js'
```

## 2. 三件套职责分工

### 2.1 `cmx-field-schema.js` — 单一事实来源

声明式的**属性定义表** `FIELD_SCHEMA`（冻结数组），每条记录描述一个可设属性：

| 字段 | 作用 |
|---|---|
| `key` | 规范属性键（UI 统一键），如 `display.format`、`edit.mode` |
| `label` | 中文标题 |
| `control` | 控件类型：`text` / `number` / `checkbox` / `select` / `select-labeled` / `select-text` / `formula` / `enum-values` / `validations` |
| `section` | 详编面板分区：`basic` / `reference` / `edit` / `display` / `compute` / `constraint` / `governance` / `control` / `flcLayout` |
| `placement` | `inline`（表格内联）/ `panel`（详编面板）/ `both` |
| `appliesTo` | 端过滤：`[A.DCT, A.DOC, A.FLC]` 子集 |
| `options` | 下拉选项，可为静态数组或 `(ctx, field) => [...]` |
| `visibleWhen` | `(row, ctx) => boolean` 动态可见性 |
| `enableWhen` | `(row, ctx) => boolean` 动态可编辑性 |
| `valueType` | `'boolean'` / `'boolean-int'` / `'boolean-visible'` / `'number'` / `'list'` |
| `tips` | 可选，有值则在 label 后渲染问号图标（`data-action="show-field-tips"`） |

**端过滤**：`appliesTo` 决定该属性在哪些 `end` 出现，取并集后按端裁剪——同一张表服务所有端。

**导出的查询函数**：`placementOf(f, end)` / `fieldsFor(end, placement)` / `panelSectionsFor(end)` / `editorPropsFor(mode, end)` / `inlineFieldsFor(end)`。

### 2.2 `cmx-field-adapter.js` — 读写桥接（规范键 ↔ 存储键）

把 schema 规范 key 映射到各端实际的存储路径，封装少数特殊键行为。

接口：

| 方法 | 说明 |
|---|---|
| `end` | 端标识 `'DCT'` / `'DOC'` / `'FLC'` |
| `get(field, key)` | 读规范属性值（渲染控件当前值） |
| `set(field, key, rawValue, vt)` | 写值；返回 `{ changed, relayout }`。`relayout: true` 表示需全量重渲染（联动） |
| `fieldKey(field)` | 该字段在表格里的唯一标识 |

两个适配器：

- **`makeDctAdapter({ typeCaps })`** — DCT/DOC 共用，`typeCaps(row)` 提供按 `dataType` 的能力开关（`len` / `int` / `dec`），控制长度/整数位/小数位是否可编辑。
- **`makeFlcAdapter()`** — FLC（含设计器列模型/检查器）。FLC 的 schema key 已与存储路径完全一致，按路径直读写。

**关键 relayout 规则**（防跳顶/失焦）：

```js
return { changed: true, relayout: key === 'edit.mode' || key === 'display.mode' }
```

只有切换录入控件 / 显示模式才全量重渲；`display.format` 等文本输入**不**触发 relayout（否则每输入一字符就重渲 → 跳顶 + 失焦）。

### 2.3 `cmx-field-ui.js` — 纯函数渲染器（输出 HTML 字符串）

**无副作用、不挂事件、不管样式**。两个入口：

- `renderFieldTable(...)` — 表格内联编辑（`placement=inline` 的属性）
- `renderFieldPanel(field, { end, adapter, ctx, keyOf })` — property 详编面板（`placement=panel`，按 `section` 分块）

核心签名：

```js
renderFieldPanel(field, { end, adapter, ctx, keyOf })
// end     'DCT'|'DOC'|'FLC'  端标识，驱动 schema 端过滤
// adapter {get,set,fieldKey}  读写桥接
// ctx     各端运行期上下文（refDictOptions / refFieldOptions / editModeOptions / typeCaps / dimensionCodes / attrOptions 等）
// keyOf   字段唯一标识 getter（DCT 由外部给 index；CTX 用 code）
```

## 3. 三端宿主必须承接的两件事

`cmx-field-ui.js` 只产 HTML，事件分发和样式都在各宿主自己的 shadowRoot 里挂接。所以**改 `cmx-field-ui.js` 产出的 HTML 结构（新增 `data-action`、新 `class`、新控件）时，四个宿主都要同步改**。

### 3.1 事件协议（各宿主 `_handleClick` / `_handleInput` 分发）

`cmx-field-ui.js` 产出的 DOM 约定：

| 属性 | 用途 | 挂接方 |
|---|---|---|
| `data-field-path="{规范key}"` | 详编面板控件值写回 | 宿主 `_handleInput` → `adapter.set` |
| `data-field-key` + `data-field-prop` | 表格内联控件值写回 | 宿主 `_handleInput` → `adapter.set` |
| `data-value-type` | 值类型（`boolean` / `number` / `list` 等），写回时 `coerce` | 宿主 `_handleInput` |
| `data-action="..."` | 行/按钮动作（`select-field` / `remove-field` / `move-field-up` / `open-formula` / `add-validation` / `remove-validation` / `add-enum` / `remove-enum` / `show-field-tips`） | 宿主 `_handleClick`（统一 `e.target.closest('[data-action]')` 分发） |

四端宿主点击分发模式一致：

```js
_handleClick (e) {
  const t = e.target.closest('[data-action]')
  const action = t?.dataset.action
  if (action === 'show-field-tips') { /* 建 ui5-popover 显示 tips */ }
  // ...add-enum / remove-enum / open-formula / ...
}
```

### 3.2 样式（各宿主 shadowRoot 各自维护）

`cmx-field-ui.js` 产出的 class（`.cmx-select-text` / `.cmx-field-tip` / `.cmx-field-tips-body` / `.fx-cell` / `.vrow` 等）必须由每个宿主的 shadowRoot 样式表承接，否则没样式。因为 shadow DOM 隔离，**样式无法跨宿主共享**，所以同一段 CSS 要在多处出现：

- DCT/DOC：`portal-definition-manager.js` 样式表
- FLC：`portal-flexible-combination-manager.js` 样式表
- 设计器：`designer-inspector-shell-style.js`

## 4. 扩展指南

### 4.1 新增一个属性（如给 `display` 加个 `unit` 子属性）

1. **`cmx-field-schema.js`** — `FIELD_SCHEMA` 加一条：
   ```js
   { key: 'display.unit', label: '单位', control: 'text', section: 'display', placement: 'panel',
     appliesTo: [A.DCT, A.DOC, A.FLC], visibleWhen: (row) => _displayModeIn(row, ['number']) }
   ```
2. **`cmx-field-adapter.js`** — 若 `display.unit` 与存储路径一致（FLC 直读），无需改；DCT 若有键名差异则加 `get`/`set` 映射。
3. **四端宿主** — 若该属性引入新 `data-action` 或新 `class`，四个宿主的 `_handleClick` / 样式表都要同步加。
4. **测试** — `cmx-field-ui.test.js` / `cmx-field-adapter.test.js` 补断言；`cmx-field-schema.test.js` 若改了 `appliesTo` 联动要同步。
5. **`eslint` + `vitest` 全量**，确保零回归。

### 4.2 新增一个控件类型（如 `color-picker`）

1. **`cmx-field-ui.js`** `renderControl` 的 `switch` 加 `case 'color-picker'`。
2. 产出 HTML 里若需宿主事件，约定新 `data-action`，四端宿主同步挂接。
3. 样式四端补。

### 4.3 新增一个端（如第 4 种元数据类型）

1. `cmx-field-schema.js` `ENDS` 加常量，相关属性 `appliesTo` 加该端。
2. `cmx-field-adapter.js` 加 `makeXxxAdapter()`。
3. 新端宿主 import `renderFieldPanel` + adapter，挂 `_handleClick` / `_handleInput` + 样式。

## 5. 关键设计约束（红线）

| 约束 | 原因 |
|---|---|
| `cmx-field-ui.js` 保持**纯函数**，不读外部状态、不挂事件、不加样式 | 一处改动波及四端；纯函数让行为可预测、可单测 |
| `relayout` **只**用于切 `edit.mode` / `display.mode` 这类结构联动 | 文本输入触发 relayout = 每字符全量重渲 → 跳顶 + 失焦 |
| 新增 `data-action` / `class` **必须四端宿主同步** | shadow DOM 隔离，事件和样式无法跨宿主共享 |
| `appliesTo` 端过滤是「并集 + 裁剪」 | 一张 `FIELD_SCHEMA` 服务所有端，新增端只是多裁一种 |
| tips 内容经 `esc()` 转义后放 `data-field-tips` 属性 | HTML 安全；长度约 300 字，远低于属性值上限 |
